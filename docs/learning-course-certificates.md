# Human approval of course completion

Classes act as teacher-managed courses. Quiz marking remains automatic, including
written-answer rubric grading. Automatic marking does not issue certificates.
A teacher explicitly reviews each enrolled learner's completed requirements and
approves a personalized Buddy completion certificate.

## Requirements and evidence

Assignment authors select **Required for course completion** and, for a linked
quiz, a minimum score percentage. Lesson and quiz assignments pin the published
resource version selected at assignment creation/update. Later publication of a
new source version does not silently replace an existing assignment's criteria.

Required lesson assignments need the learner's version-specific completed lesson
progress. Required quiz assignments need a submission for the pinned version,
completed automatic grading, and the configured score threshold. Written grading
that remains pending blocks approval; it never counts as a passing score.
Required homework and book assignments need a teacher-reviewed submission for the
current assignment revision. Optional assignments do not block course completion.
At least one required assignment must be configured before issuing a certificate.

Reaching a lesson's completion screen records learner completion, not proctored
attendance or independently verified understanding. The teacher reviews this
record alongside quiz outcomes and homework before approving the course.

## Issuance

In the class view, **Course completion & Buddy certificates** shows each
learner's requirements. The teacher reviews the checklist, confirms the recipient's
name, optionally adds a private approval note, and explicitly approves issuance.
There is no AI or background certificate issuance.

Approval rechecks teacher ownership/admin permission, current teacher folder
access, learner enrollment, current learner folder access, course revision and a
digest of the learner's actual progress/marks. Changes since the teacher loaded
the review produce a conflict requiring a refresh. The course is locked during
approval, and evidence rows have shared locks until the immutable issuance commits.

The saved certificate snapshots recipient name, course title, teacher display
name, issuance time, course revision, version-pinned evidence and a unique UUID.
Retrying approval for unchanged evidence returns the same certificate. Reviewing
new evidence/course revisions can issue a new version while retaining historical
records. Editing a learner profile or course later does not rewrite an existing
certificate. Incorrect certificates can be explicitly revoked with a reason;
revoked downloads visibly state their status. Revocation does not erase history.

## Downloads and access

Learners can download only their own certificate while they retain class and
folder access. The course teacher and administrators can download certificates
for that course. Knowing another certificate UUID confers no access. There is no
public unauthenticated directory or verification endpoint.

Both a printable HTML certificate and a PDF are available. HTML renders escaped
persisted fields only, includes no script/external resources, and is delivered
with a sandbox policy and private/no-store caching. PDF uses the existing bounded,
offline Chromium renderer. If PDF rendering is unavailable, the printable HTML
remains usable with the browser's print/save-as-PDF command.

API endpoints:

- `GET /api/learning/classes/{id}/completion`: teacher roster or learner self.
- `POST /api/learning/classes/{id}/completions/{username}/approve`: explicit
  approval with `expected_revision`, `evidence_digest`, `recipient_name`, optional
  private `note`.
- `GET /api/learning/certificates/{id}/download?format=html|pdf`: authorized download.
- `POST /api/learning/certificates/{id}/revoke`: course manager, nonblank `reason`.

Tests: `PYTHONPATH=plugins/learning python3 -m unittest tests.test_learning_course_completion`.
All fixtures are synthetic. Tests never issue actual learner certificates.

## Email notifications

When a course manager adds learners through the course access or members screen,
newly enrolled users receive an individual email after the enrollment is saved.
Existing members are not emailed again when the roster is saved unchanged. Emails
use the profile address, or the username if it is an email address. SMTP must be
enabled in administration. Missing addresses and delivery errors are logged;
enrollment emails are not queued or automatically retried.

Certificate emails contain a PDF attachment generated by the same offline renderer
as PDF downloads. If rendering or sending fails, the certificate records a failed
email status and can be sent again from the certificate screen. SMTP acceptance
does not guarantee final delivery.
